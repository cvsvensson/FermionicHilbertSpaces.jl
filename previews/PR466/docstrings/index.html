FermionicHilbertSpaces.FermionicHilbertSpaces — Module
FermionicHilbertSpaces

Symbolic fermions, bosons and spins, Hilbert spaces with constraints, and the tensor products, partial traces and matrix representations that connect them.

hc

op + hc is op + op' and op - hc is op - op', for example f[1]'f[2] + hc.

FermionicHilbertSpaces.AdditiveConstraint — Type
AdditiveConstraint(allowed_values; spaces=missing, maps=missing)
AdditiveConstraint(allowed_values, maps)

Constraint enforcing that the sum of per-subspace contributions lies in allowed_values. The contribution of each subspace in spaces is the value of its map applied to the subspace's state. A single function in maps is applied to all spaces; a collection of maps supplies one function per subspace.

If spaces is missing, tensor_product uses the spaces it combines, and constrain_space treats the whole space as a single subspace.

FermionicHilbertSpaces.BranchConstraint — Type
BranchConstraint(f)

Constraint for pruning branches while generating basis states. f(partial_state, depth, spaces) -> Bool is evaluated during backtracking by generate_states, after the state at position depth has been assigned. Entries after depth in partial_state have not yet been assigned.

Returning true continues exploring the branch, while returning false prunes it. The callback should therefore accept partial states and reject a branch only when no valid completion can satisfy the constraint.

tensor_product(spaces; constraint) prunes with the given spaces. constrain_space(H, constraint) instead keeps the states of H for which f accepts every prefix, with spaces the factors of H.

FermionicHilbertSpaces.FilterConstraint — Type
FilterConstraint(reducer; maps=missing, spaces=missing)
FilterConstraint(reducer, maps, spaces)

Constraint that keeps complete basis states for which reducer returns true.

With only reducer, the reducer is called directly as reducer(state). When maps and spaces are provided, the state is split into the selected spaces, each map is applied to its corresponding subspace, and the reducer is called on the resulting values. A single function is applied to all spaces; a collection of maps supplies one function per subspace.

GenericHilbertSpace(label, basisstates[, state_index])
GenericHilbertSpace{B}(label, basisstates[, state_index])

Atomic Hilbert space whose basis states are given explicitly by basisstates, indexed by integers. label is returned by symbolic_group and atomic_id and identifies the space in symbolic expressions. state_index gives the integer index of a basis state. NumberConservation(space)

FermionicHilbertSpaces.constrain_space — Function
constrain_space(space, constraint[, states])
constrain_space(space, states)

Build a constrained Hilbert space from space.

With a constraint, keep the basis states of space that satisfy it. If states is given, only those states are candidates. Constraints that group states into sectors, such as NumberConservation, return a space with sectors, with states ordered by sector. constrain_space(space, NoSymmetry()) returns space unchanged. A constraint can also be quantity or quantity => spec, where quantity is a diagonal operator or a function of the basis state, such as constrain_space(H, N => 2) with N = sum(f[i]'f[i] for i in 1:4); see Constraints and sectors for what spec can be. A quantity => spec constraint on a space with sectors keeps its labels, and its own labels follow them.

With only states, return the subspace spanned by exactly those basis states, in the given order; this is equivalent to constrain_space(space, NoSymmetry(), states).

FermionicHilbertSpaces.embed — Method
embed(m, Hsub => H; complement=complementary_subsystem(H, Hsub), kwargs...)

Compute the embedding of a matrix m in the basis Hsub into the basis H. Fermionic phase factors are included if the two spaces are fermionic Hilbert spaces. Hsub => H reads input => output; see Pair arguments. Hsub can also be given as symbols naming its modes, meaning subregion(Hsub, H).

The result is the compression P (m ⊗ I) P onto H, so that tr(embed(A, Hsub => H) * ρ) == tr(A * partial_trace(ρ, H => Hsub)) for ρ on H. Unless projection=true, throws an ArgumentError if m ⊗ I maps a state of H outside H with nonzero amplitude. Columns of m for states of Hsub that no state of H contains are dropped, and states of H whose part on Hsub is not in Hsub get zero.

m can be a dense GPU array, for which alg defaults to NoScalarIndexingAlg.

If m is a vector, Hsub and H must have the same modes, as for a sector Hsub of H. The result is m placed at the indices indices(Hsub, H) and zero elsewhere.

julia> using FermionicHilbertSpacesjulia> @fermions f;julia> H = hilbert_space(f, 1:2, NumberConservation());julia> embed([1, 2], sector(1, H) => H)4-element Vector{Int64}: 0 1 2 0

FermionicHilbertSpaces.expectation — Method
expectation(op, state, H)

Return the expectation value of the operator op in state on the space H. A vector ψ gives ψ' * M * ψ and a density matrix ρ gives tr(ρ * M), where M = representation(op, H). The state is assumed to be normalized.

On hilbert_space(f, labels, FreeFermions.SingleParticle()), state is the correlation matrix G[i, j] = ⟨f_i' f_j⟩, and on hilbert_space(f, labels, FreeFermions.BdG()) it is the Nambu correlation matrix G[i, j] = ⟨Ψ_i' Ψ_j⟩, with Ψ = (f; f') in the order of the BdG space. On the Majorana space hilbert_space(γ, labels, FreeFermions.SingleParticle()) it is G[i, j] = ⟨γ_i γ_j⟩ / 2. The state is then the Gaussian state with that correlation matrix, and op of any degree is evaluated with Wick's theorem. Terms that do not conserve the particle number (single-particle space) or the parity (BdG and Majorana spaces) throw an error, unless projection=true, which drops them.

Examples

@fermions fH = hilbert_space(f, 1:2)ψ = representation("10", H)expectation(f[1]' * f[1] + 2, ψ, H) == 3

FermionicHilbertSpaces.generalized_kron — Function
generalized_kron(ms, Hs, H::AbstractHilbertSpace=tensor_product(Hs))

Compute the fermionic tensor product of the matrices or vectors in ms on the spaces Hs, as an array on H, which defaults to the tensor_product of Hs.

For vectors, the result is the product state, the same as tensor_product(ms, Hs => H). For matrices, write each local basis operator as a product of single-mode factors (one of c c†, c†, c, c†c per mode) in the mode order of its space; generalized_kron multiplies the factors of all spaces together in the mode order of H, and extends this linearly. The result does not depend on the order of ms and Hs, and is in general not a product of embeddings: for A = c₁†c₃ on modes [1, 3] and B = c₂†c₄ on modes [2, 4] it gives c₁†c₂†c₃c₄ = -(c₁†c₃)(c₂†c₄). It equals tensor_product(ms, Hs => H) when each space in Hs covers consecutive modes of H and Hs is listed in that order. Otherwise generalized_kron of density matrices need not be a density matrix. Use tensor_product for product states, local observables, and anything that should equal a product of embedded operators.

generalized_kron(ms, Hs => H) is also accepted, and generalized_kron(Hs => H) returns a function of ms. Hs => H reads input => output; see Pair arguments.

The result is the compression of the tensor product onto H. Unless projection=true, throws an ArgumentError if the tensor product of matrices maps a state of H outside H with nonzero amplitude, or if the tensor product of vectors has a nonzero amplitude outside H.

FermionicHilbertSpaces.hilbert_space — Method
hilbert_space(b::BosonSym, dimension[, constraint])
hilbert_space(b::Field{Boson}, labels, dimension[, constraint])

The truncated space of the bosonic mode b, with basis states |0⟩, …, |dimension-1⟩, so the maximal occupation is dimension - 1. With labels, the tensor product of one such space for each mode b[l], l in labels. An optional constraint restricts the basis states.

FermionicHilbertSpaces.matrix_representation — Function
matrix_representation(op, space::AbstractHilbertSpace, [repr]; kwargs...)
matrix_representation(op, Axes(Hout, Hin), [repr]; kwargs...)

Return the matrix representation of symbolic operator op in Hilbert space space. This is the operator-specific form of representation.

With Axes(Hout, Hin), return the dim(Hout) × dim(Hin) matrix of op from Hin to Hout. The two spaces must have the same groups, for example two sectors of the same modes. Two different spaces support only eager formats without chunking.

FermionicHilbertSpaces.open_system — Method
open_system(sym, args...; kwargs...)
open_system(H; kwargs...)

Set up the doubled space for density matrices of a system with Hilbert space H, or of hilbert_space(sym, args...; kwargs...). For H, kwargs are passed to tensor_product. Returns (Hlr, Hl, Hr, left, right):

  • Hl and Hr are copies of the system space tagged :left and :right. Hr is transposed, so that representation(right(A * B), Hr) == representation(right(B), Hr) * representation(right(A), Hr).
  • Hlr = tensor_product(Hl, Hr) is the space of vectorized density matrices.
  • left(op) and right(op) map a symbolic operator of the system to the copy acting on Hl or Hr, so left(A) * right(B) represents ρ -> A ρ B and -1im * (left(H) - right(H)) is the Liouvillian of a Hamiltonian H.

Use reshape(ρ, (Hl, Hr) => Hlr) and reshape(v, Hlr => (Hl, Hr)) to convert between density matrices and vectors.

julia> using FermionicHilbertSpaces: dissipator; @fermions f;julia> Hlr, Hl, Hr, left, right = open_system(f, 1:1);julia> n = f[1]' * f[1];julia> L = representation(-1im * (left(n) - right(n)) + dissipator(f[1]), Hlr);julia> size(L)(4, 4)

FermionicHilbertSpaces.partial_trace — Method
partial_trace(m, H => Hsub; complement=complementary_subsystem(H, Hsub))
partial_trace(H => Hsub; kwargs...)  # -> PartialTraceMap

Compute the partial trace of m from H to Hsub. Fermionic phase factors are included if both H and Hsub are Fermionic, unless specified otherwise in kwargs. H => Hsub reads input => output; see Pair arguments. A vector m is treated as a pure state ψ, and the result is the reduced density matrix of ψψ†. Hsub can also be given as symbols naming its modes, meaning subregion(Hsub, H), as in H => [f[1], f[3]].

The trace drops the states of H whose part on Hsub is not in Hsub, or whose part on the complement is not in complement. Unless projection=true, throws an ArgumentError if m has a nonzero element in the row or column of such a state. The map partial_trace(H => Hsub) does not check its input.

m can be a dense GPU array, for which alg defaults to NoScalarIndexingAlg.

julia> using FermionicHilbertSpaces; @fermions f;julia> H = hilbert_space(f, 1:2); Hsub = hilbert_space(f, 1:1);julia> partial_trace(representation(f[1]' * f[1], H), H => Hsub) == [0 0; 0 2]true

FermionicHilbertSpaces.partial_transpose — Method
partial_transpose(m, H, Hsub; complement=complementary_subsystem(H, Hsub), phase_factors=true, projection=false)
partial_transpose(m, H => Hout, Hsub; kwargs...)
partial_transpose(H, Hsub; kwargs...)  # -> PartialTransposeMap
partial_transpose(H => Hout, Hsub; kwargs...)  # -> PartialTransposeMap

Partial transpose of m (an operator on H, a pure state, or a vectorized density matrix) on the subsystem Hsub, which may be any subset of the modes of H (contiguous or not), given as a space or as symbols naming the modes, meaning subregion(Hsub, H). The result is an operator on Hout, which defaults to H. H => Hout reads input => output; see Pair arguments.

Without m, a callable PartialTransposeMap is returned. It takes the same keyword arguments.

For fermions this is the fermionic partial transpose (partial time reversal) R_A(Ẽ^{ν,ν'}) = i^{k_A} Ẽ^{(ν'_A,ν_B),(ν_A,ν'_B)} in the fermionic operator basis, which is independent of the mode ordering. With phase_factors=false, or for spaces without phase factors, it is the ordinary partial transpose.

The partial transpose does not preserve number or parity constraints. For constrained H, pass a larger output space on the same modes as H => Hout. For fermions the result is not Hermitian: (ρ^{R_A})' == p_A ρ^{R_A} p_A for Hermitian ρ, with p_A the parity of Hsub. Applying the fermionic partial transpose twice gives p_A ρ p_A, not ρ.

FermionicHilbertSpaces.representation — Function
representation(op_or_state, space::AbstractHilbertSpace, [repr]; kwargs...)
representation(op, Axes(Hout, Hin), [repr]; kwargs...)
representation(state_expression; kwargs...)

Return a concrete representation of op_or_state in Hilbert space space. This is the main entry point, which calls matrix_representation for operators and vector_representation for states.

  • For symbolic operators and numbers, returns a sparse matrix by default. The optional repr selects the format: an array type such as Matrix or SparseMatrixCSC, with an optional element type as in Matrix{ComplexF64}, or a number type such as Float64 for a sparse result of that element type. :lazy gives a matrix-free SciMLOperators.FunctionOperator that wraps a LazyOperator, and :sparse also works. A number c gives c times the identity. With a GPU package loaded, a GPU array type such as CuArray or cuSPARSE.CuSparseMatrixCSR{Float32} builds the matrix on the GPU.
  • For AbstractBasisState and strings such as "10", returns a one-hot sparse column vector.
  • For SymbolicState kets and bras, and sums of them, returns the corresponding column or row vector. Their array types are Vector and SparseVector. Array gives a dense result for both states and operators.
  • For ketbras, and operators that contain ketbras, returns a matrix.

Coefficients are converted to a format's element type, so a complex coefficient with element type Float64 throws an InexactError. Matrix elements are computed in the precision of a float element type. Without an element type, Float32 coefficients give Float32 matrix elements.

Expressions that combine kets or bras with operators or with states of other spaces have no representation and throw an ArgumentError. Without the space argument, only expressions of symbolic states are accepted, and the space is taken from the states. The single-particle space hilbert_space(f, labels, FreeFermions.SingleParticle()) and the Bogoliubov-de Gennes space hilbert_space(f, labels, FreeFermions.BdG()) represent quadratic fermionic operators only, and a number is represented by the zero matrix.

With Axes(Hout, Hin), op is represented as a map from Hin to Hout.

julia> @fermions f;julia> representation(f[1]' * f[1], hilbert_space(f, 1:1)) == [0 0; 0 1]true

FermionicHilbertSpaces.symmetric_sector — Method
symmetric_sector(H, Hs, sector=:symmetric, T=default; orth_method=:qr, check=true, normalize=true, sparse=true, phase_factors=true)

Return a basis for the sector of H selected by sector, under permutations of the factors Hs.

sector is either a tuple (perms, weights), with permutations of 1:length(Hs) and one weight per permutation, or :symmetric or :antisymmetric, which stand for all permutations with weight one or the permutation sign. T is the element type of the result. It defaults to Float64 for :symmetric and :antisymmetric, and for a tuple (perms, weights) to the floating point version of the element type of weights, for example ComplexF64 for complex weights.

With Hs a partition of H and orth_method not nothing, the projector is not built, the basis is a SparseMatrixCSC with element type float(T), and sparse has no effect. For :symmetric and :antisymmetric normalize has no effect either, since scaling does not change the span. Otherwise the projector is built with permutation_projector(H, Hs, perms, weights, T; normalize, sparse), and :symmetric and :antisymmetric require Combinatorics.jl to be loaded. orth_method selects what is returned:

  • :qr: a matrix with orthonormal columns spanning the sector, from a QR decomposition of the projector.
  • :eig: a matrix with orthonormal columns spanning the sector, from the eigenvectors of the projector with nonzero eigenvalue.
  • nothing: the projector itself.

:qr and :eig find the numerical rank with a tolerance relative to the scale of the projector, so they assume that the projector is proportional to an orthogonal projector. This holds when perms form a group and weights are a positive multiple of a character of it or of its complex conjugate.

With check=true and a tuple (perms, weights), symmetric_sector throws an ArgumentError if perms does not contain the identity permutation or its weight is not real and positive, and, for orth_method not nothing, if the projector is not Hermitian or, for weights of equal magnitude, not a multiple of a one-dimensional character. check=false skips these checks.

Hs may be either a full partition of H or a proper subsystem list; in the latter case the sector is constructed on tensor_product(Hs...) and embedded back into H. phase_factors includes the fermionic signs of the permutations, as in permutation_operator.

FermionicHilbertSpaces.tensor_product — Method
tensor_product(ms, Hs, H::AbstractHilbertSpace; kwargs...)
tensor_product(ms, Hs => H; kwargs...)
tensor_product(Hs => H; kwargs...)

Compute the ordered product of the fermionic embeddings of the matrices ms in the spaces Hs into the space H. If H is unconstrained, tensor_product((A, B), (HA, HB) => H) == embed(A, HA => H) * embed(B, HB => H). If H is constrained, the result is the ordered product on the unconstrained space restricted to H, as representation of the corresponding symbolic product. Terms that take a state of H outside H throw an ArgumentError unless projection=true, which drops them. A matrix on a constrained space in Hs acts as zero on states outside that space. For vectors, the result is the product state: if each ms[k] = ψₖ|0⟩ with ψₖ an operator on the modes of Hs[k], the result is ψ₁ψ₂⋯|0⟩. Swapping two odd states flips the sign. kwargs can be passed a bool phase_factors. The last form returns a function of ms. Hs => H reads input => output; see Pair arguments.

FermionicHilbertSpaces.@fermions — Macro
@fermions a b ...

Create one or more fermion species with the given names. Indexing into fermions species gives a concrete fermion. Fermions in one @fermions block anticommute with each other, and commute with fermions in other @fermions blocks. a[l] is the annihilation operator of the mode labelled l, a[l]' its creation operator, and a[i, σ] is the mode labelled (i, σ).

Examples:

  • @fermions a b creates two species of fermions that anticommute:
    • a[1]' * a[1] + a[1] * a[1]' == 1
    • a[1]' * b[1] + b[1] * a[1]' == 0
  • @fermions a; @fermions b creates two species of fermions that commute with each other:
    • a[1]' * a[1] + a[1] * a[1]' == 1
    • a[1] * b[1] - b[1] * a[1] == 0

See also @majoranas.

FermionicHilbertSpaces.@majoranas — Macro
@majoranas a b ...

Create one or more Majorana species with the given names. Returns the species, or a tuple of them if several names are given. Indexing into Majorana species gives a concrete Majorana. Majoranas in one @majoranas block anticommute with each other, and commute with Majoranas in other @majoranas blocks.

Majoranas are Hermitian and normalised to square to one: γᵢγⱼ + γⱼγᵢ = 2δᵢⱼ.

Examples:

  • @majoranas a; @majoranas b creates two species of Majoranas that commute with each other:
    • a[1] * a[1] == 1
    • a[1] * b[1] - b[1] * a[1] == 0

FermionicHilbertSpaces.@spin — Macro
@spin s

@spin s J

Create a symbolic spin s for constructing spin operators such as s[:x], s[:y], s[:z], s[:+], and s[:-]. The spin J can be given here or later to hilbert_space.

The operators are spin operators, not Pauli matrices: s[:z] has eigenvalues -J, …, J, so for spin 1/2 s[:x] is σˣ/2, and s[:±] = s[:x] ± i s[:y]. The basis states of hilbert_space(s, J) are ordered by increasing s[:z] eigenvalue, starting at -J.

For J ≥ 1, == and iszero on symbolic expressions compare their stored form, which is not unique, so equal operators can compare unequal: iszero(s[:z]*s[:+]^2 - s[:+]^2) is false for J = 1.
