FermionicHilbertSpaces.AbstractSubspace — Type
AbstractSubspace{B,P} <: AbstractHilbertSpace{B}

A space spanned by some of the basis states of parent(H)::P. A subtype implements

  • parent(H): the space that H is a subspace of. It is never an AbstractSubspace.
  • subspace_states(H): the basis states of H, in order, each appearing once.
  • subspace_index(H): an index with a state_position method for the states of H, such as default_subspace_index(constraint, parent(H), subspace_states(H)), built once by the constructor.
  • rewrap(H, newparent): the space with the same states and index as H over newparent, which has the same basis states and state_index as parent(H).

It may also implement subspace_key(H), the values compared by == and hash, which defaults to (parent(H), subspace_states(H)), and show_details(io, H), printed after the parent by show.

The states are meant to be basis states of parent(H), but this is not checked. Some spaces store other states over a FermionicSpace parent: hilbert_space(f, labels, states) with FixedNumberFockStates, BdG spaces with NambuStates and SingleParticle spaces with SingleParticleStates.

A subtype gets dim, basisstates, basisstate, state_index, ==, hash, show, add_tag and TransposedSpace. The functions that describe its modes and apply operators are forwarded to parent(H), so that matrix representations, tensor products, partial traces, subregion and constrain_space work on it.

FermionicHilbertSpaces.BranchConstraint — Type
BranchConstraint(f)

Constraint for pruning branches while generating basis states. f(partial_state, depth, spaces) -> Bool is evaluated during backtracking by generate_states, after the state at position depth has been assigned. Entries after depth in partial_state have not yet been assigned.

Base.reshape — Method
reshape(t, mappings...; repeat=false, skipmissing=false)

Reshape the array t by splitting or combining its indices according to Hilbert-space mappings. The mappings are applied left to right, each one consuming the next consecutive group of input indices. Each mapping reads input => output; see Pair arguments.

Mapping forms

H => (H1, H2, ...)   split one index into several(H1, H2, ...) => H   combine several consecutive indices into one(H1, H2, ...) => (K1, K2, ...)  repartition several indices into severalH => H               leave one index unchanged

Specifying multiple mappings

Give one mapping per group of input indices:

reshape(A, H1 => (H1a, H1b), (H2a, H2b) => H2, H3 => H3)

This splits the first index, combines the next two, and leaves the last unchanged.

Single-mapping shorthand

When only one mapping is given, it is replicated if needed:

  • If it consumes all indices of t, it is applied once:

    reshape(v, H => (H1, H2))        # length-1 vector → 2-index tensor

  • If t has twice as many indices as the mapping consumes, the mapping is applied to the first half and again to the second half. This covers the common case of a square operator matrix, where the first index is the output space and the second is the input space:

    reshape(m, H => (H1, H2))        # matrix → 4-index tensor
# equivalent to reshape(m, H => (H1, H2), H => (H1, H2))

reshape(T, (H1, H2) => H)        # 4-index tensor → matrix
# equivalent to reshape(T, (H1, H2) => H, (H1, H2) => H)

For asymmetric operators, specify both mappings explicitly:

reshape(m, Hout => (H1, H2), Hin => (K1, K2))

Many-to-many mappings are evaluated directly and are equivalent to an explicit combine-then-split composition:

reshape(A, (H1, H2) => (K1, K2))# equivalent to reshape(reshape(A, (H1, H2) => Hmid), Hmid => (K1, K2))

where Hmid is the canonical combined space of the input tuple.

When repeat=true, the single given mapping is applied to every consecutive group of input indices. For example, with a 3-index array where every index lives on H:

reshape(A, H => (H1, H2); repeat=true)# equivalent to reshape(A, H => (H1, H2), H => (H1, H2), H => (H1, H2))

Missing states

Some basis states of the input spaces may have no counterpart in the output spaces, e.g. when splitting into a truncated space or combining into a symmetry-constrained space. By default an ArgumentError is thrown if t has a nonzero entry on such a state, since that amplitude would be lost. Zero entries are fine, so e.g. combining unconstrained spaces into a parity-conserving space works for parity-preserving operators. With skipmissing=true, the components on missing states are silently dropped.

Precomputed form

reshape(mappings...; repeat=false, skipmissing=false)

returns a callable ReshapeMap that precomputes the transitions, and can be applied as op(t) or in place as op(out, t).

generalized_kron(ms, Hs, H::AbstractHilbertSpace=tensor_product(Hs))

  • For symbolic operators and numbers, returns a sparse matrix by default. The optional repr selects the format: :dense gives a dense matrix, and :lazy (or LazyRepr()) gives a matrix-free SciMLOperators.FunctionOperator that wraps a LazyOperator. A number c gives c times the identity.

FermionicHilbertSpaces.symmetric_sector — Method
symmetric_sector(H, Hs, sector=:symmetric, T=default; orth_method=:qr, check=true, normalize=true, sparse=true)

Return a basis for the sector of H selected by sector, under permutations of the factors Hs.

sector is either a tuple (perms, weights), with permutations of 1:length(Hs) and one weight per permutation, or :symmetric or :antisymmetric, which stand for all permutations with weight one or the permutation sign. T is the element type of the result. It defaults to Float64 for :symmetric and :antisymmetric, and for a tuple (perms, weights) to the floating point version of the element type of weights, for example ComplexF64 for complex weights.

For :symmetric and :antisymmetric with Hs a partition of H and orth_method not nothing, the basis is built directly from the orbits of the basis states under permutations, with one column per orbit that contributes to the sector. The basis then has element type float(T), and the keywords normalize and sparse have no effect. In the remaining cases, the projector is built with permutation_projector(H, Hs, perms, weights, T; normalize, sparse), and :symmetric and :antisymmetric require Combinatorics.jl to be loaded. orth_method selects what is returned:

  • :qr: a matrix with orthonormal columns spanning the sector, from a QR decomposition of the projector.
  • :eig: a matrix with orthonormal columns spanning the sector, from the eigenvectors of the projector with nonzero eigenvalue.
  • nothing: the projector itself.

:qr and :eig find the numerical rank with a tolerance relative to the scale of the projector, so they assume that the projector is proportional to an orthogonal projector. This holds when perms form a group and weights are a positive multiple of a character of it or of its complex conjugate.

With check=true and a tuple (perms, weights), symmetric_sector throws an ArgumentError if perms does not contain the identity permutation or its weight is not real and positive, and, for orth_method not nothing, if the projector is not Hermitian. check=false skips these checks.

Hs may be either a full partition of H or a proper subsystem list; in the latter case the sector is constructed on tensor_product(Hs...) and embedded back into H.
